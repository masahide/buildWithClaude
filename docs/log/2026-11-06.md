## AI エージェントにスチームの音を解析させる実験

本人から「スペクトログラムを作って AI エージェントで解析させたら効果があるか」を確かめたいと言われた。11-05 のボイスメモ1本（67 秒）で試した。

### やり方

- エージェント: Managed Agents。コーチとは別に「スチーム音の解析（実験）」を作った（Claude Opus 5.5）。作業用の環境で Python を使い、自分で図を描いて確かめながら答える
- 入力（音声ファイルは送らない）
  - 条件1 **包絡**: アプリが実際に送るのと同じ3帯域（0.1 秒刻み、背景音比）。`scripts/voice_memo/judge/` で、アプリの判定をそのままコンパイルして出した
  - 条件2 **スペクトル**: 64 帯域（50 Hz〜8 kHz を対数で等分、0.1 秒刻み、帯域ごとの背景音比 dB）。`scripts/voice_memo/spectrum.py` で作った
- 指示: 録音の流れ（空だし → キュルルル → ジュルジュル → 渦 → キュルキュル → 止める）だけを伝え、各境の時刻と撹拌中のゴボゴボの時刻を答えさせた
- 各条件3回、同時に回した: `scripts/voice_memo/agent_experiment.py`。結果は `notes/private/experiments/`（git 管理外）
- 正解: キュルルルの始まりと空だしは本人が確認済み。それ以外は Claude Code が図から読んだ位置で、本人の耳ではまだ確かめていない

### 分かったこと

1. **はっきりした境は、エージェントがほぼ完璧に当てる。** 空だし、蒸気の始まり、キュルルルの終わり、止めた時刻は、6回とも ±0.2 秒に収まった。アプリの判定は、止めた時刻が +1.8 秒ずれていた（1 秒平均の分だけ遅れる）
2. **泡入れ→渦の境は、音そのものがあいまい。** エージェントの答えは 23.3 / 29.6〜29.9 / 32.0 秒に分かれた。根拠を読むと、どの回も同じ2か所で迷っていた
   - 23〜26 秒に、泡入れの途中で一度静かになる区間がある（ここを渦の始まりと見ると 23.3 秒）
   - 31.4 秒・31.9 秒の跳ねを、泡入れの名残と見るか、渦の中のゴボゴボと見るか（名残なら 32.0 秒）
   どの回も、迷った点を evidence に書いていた。アプリの判定（32.9 秒）は、この「名残」側を取った形に近い
3. **ゴボゴボの数は安定しない（4〜10 回）。** 45.8 秒と 49.5〜49.7 秒はどの回も挙げた。数を数えるより、「どこに集まるか」を見るほうが安定する
4. **3帯域の包絡で十分。** 64 帯域にしても精度は上がらず、時間とツールの呼び出しが増えた（7〜8 回 → 16〜24 回）。本番で端末から出す包絡のままでよい
5. **1回 2.5〜4 分かかる。** 毎杯の判定をエージェントに任せると、コーチの診断（1〜2 分）にさらに足される。毎杯の判定には使えない

### 結論

- **毎杯の判定は端末の数値のまま（D16 のとおり）。** エージェントは時間がかかり、肝心の泡入れ→渦の境が回ごとにぶれる
- **開発では、エージェントの解析が効く。** 境の候補と迷う理由を、根拠つきで出してくれる。本人の耳の確認とあわせて、判定の答え合わせ（sound-picture.md A）に使える
- 泡入れ→渦の境は、本人の耳で決める必要がある。候補は 23 秒、30 秒、32 秒。アプリの判定は 33 秒なので、本人の答えによって判定を前に寄せるか決める
- 止めた時刻の +1.8 秒は、1 秒平均のぶんを差し引けば直せる
