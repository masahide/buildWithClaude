# 2026-11-07

## 音の画像だけを見せて判定させる実験

本人から「スペクトログラムの画像で判定するのが有効か確かめてほしい」と頼まれた。11-05 のボイスメモで試した。

### やり方

- 答えの線や印を入れない画像を2種類描いた（`scripts/voice_memo/image_experiment.py`）
  - スペクトログラム（50 Hz〜8 kHz、0.1 秒刻み、背景音比 dB）
  - 4帯域の音量グラフ（低 50-400 Hz、中 400-2000 Hz、高 2-4 kHz、最高 4-8 kHz）。アプリが送る包絡から描ける形
  - どちらも横軸に1秒ごとの目盛り線を入れた
- 条件: スペクトログラムだけ / 4帯域だけ / 両方。各3回
- 毎杯の判定に使えるかを見るため、Messages API の1回の呼び出しで答えさせた（Claude Opus 5.5、effort high、構造化出力）
- 伝えたのは音の並びと、泡入れが1回とは限らないこと、チリチリとゴボゴボの説明だけ。正解は 11-06 に本人が耳で確かめた位置（泡入れ 16〜23 秒、追加 27〜32 秒、渦へ 32 秒、チリチリ 41〜42 秒・45〜46 秒）
- 結果は `notes/private/experiments/`（git 管理外）

### 分かったこと

1. **はっきりした境（空だし、蒸気の始まり、止めた時刻）は、画像だけでも当たる。** 9 回とも ±0.3 秒以内（4帯域で止めた時刻だけ約 +1 秒）
2. **キュルルルを正しく見分けられない。** 本人の確認ではキュルルルは 11.5〜16 秒。画像だけを見ると、9 回中 8 回が「12.6〜12.8 秒で終わり、その後は泡入れ」と読んだ。キュルルルが画像でどう見えるかを知らないと判断できない
3. **追加の泡入れの終わりを 3 秒ほど早く切る。** どの回も 28.4〜29.3 秒で切り、29〜32 秒の跳ねを「チリチリ」と数えた。アプリの判定（32.4 秒）のほうが耳に近い
4. **チリチリは半分ほどしか拾えず、誤りが多い。** 正しく拾えたのは 41 秒と 45.8 秒のうち 0〜2 か所。追加の泡入れの跳ね（30〜32 秒）を毎回チリチリと誤った
5. **回ごとに区切り方が変わる。** 同じ画像でも、泡入れを1〜3区間に分けた。泡入れの合計時間や追加の回数は、杯どうしの比較に使えるほど安定しない
6. 1 回 20〜32 秒、入力は約 3,000〜4,000 トークン。エージェント（2.5〜4 分）よりずっと速いが、毎杯の診断にさらに足される

### 結論

- **画像だけでの判定は、アプリの数値の判定より劣る。** 特に、この製品で大事な泡入れの長さ・追加の泡入れ・渦への境で負ける。回ごとのばらつきもあり、予測の検証（D7）に使う杯どうしの比較が崩れる。D16 の「判定は端末の数値のまま」を変えない
- 画像が効くのは次の2つ
  - 人と Claude Code が判定を答え合わせするとき（11-06 に、泡入れが2回あること、チリチリが 4〜8 kHz の山であることを画像で突き止めた）
  - デモと README で、見えないスチームの音を形として見せるとき
- コーチに画像を渡す（D16 の C）なら、判定の代わりではなく「数値に出ない形を読む補助」としてにする。画像だけではキュルルルを誤るので、渡すならアプリの判定の線を描き込む必要がある（sound-picture.md の設計どおり）
- 今回は録音1本・プロンプト1種類での結果。キュルルルの見え方をプロンプトで教えれば2は改善しうる。ただ、締切（11-08）を考えると、これ以上は追わない

## スチームのやり方の個人差（本人から）

本人のやり方は一例で、スチームの手法はいろいろある。多くの人に共通するのは次の3つ。

- 最初と最後に空だしをする
- 蒸気を出した直後に「ぎゅるるるー」と鳴る
- 泡入れ（空気が入る「チリチリ」）は最初だけ。途中でチリチリ言わせないようにする人もいる

### 反映

- 判定はこの共通部分を前提にしている（空だしを除く、始めの甲高い音を別に測る、泡入れを「最初」と「追加」に分けて数える）。追加の泡入れをしない人は `re_air_count` が 0 になるだけなので、そのまま当てはまる
- 最後の空だしはまだ録音がない。合成音のテストに「止めて、拭いて、最後に空だし」を足し、区間に含めないこと、終了通知が1回だけであることを確かめた（7本通過）
- コーチのプロンプトを、共通部分と「この人のやり方」に分けた。追加の泡入れや撹拌中のチリチリは、この人の癖として扱い、一般論として押し付けない
- 製品としては、この人ごとのやり方を `/profile.md`（メモリストア）に持たせる形が合う（architecture.md のとおり）
