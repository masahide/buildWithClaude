## プロジェクト概要（冒頭の1文＋本文、合計500字以内）

このプロジェクトは、家でラテアートを練習する人の「失敗の原因がミルクスチームのどこにあるか分からない」悩みを、スチームの音から原因と次の一手を返し、次に淹れたときに確かめられるようにする、iPhone アプリと Claude のコーチです。

台所で「練習を開始」を押して iPhone を置き、いつもどおりスチームして注ぎます。ピッチャーの残りを1枚撮るだけです。1〜3分後、コーチから3つだけ届きます。原因の工程1つ（エア入れか撹拌か）。次の1回で直す点1つ（耳と手と時間でできる言葉）。次に淹れたときに起きるはずの変化1つ。次の回で予測が当たったかを確かめ、当たった直し方は「あなたの正解」に溜まります。
スチームのやり方もマシンの音も人によって違うので、他人と比べて採点はしません。コーチも最初は初心者です。本人が耳で教え、毎晩の振り返りでコーチが音の読み方を育てます。開発中には、コーチがスペクトログラムを見て「アプリの判定が早すぎる」と自分から指摘し、判定が直りました。音は自宅の外に出さず、Claude には音から作った数値と絵だけを渡します。

## 開発中に一番詰まった場面

**何を作ろうとしていたか**
iPhone のマイクで、スチームの区間と工程（エア入れ／撹拌）を自動で判定する仕組み。

**Claude にどう指示したか**
スチームの手順と音の聞こえ方を言葉で説明し、判定を書いてテストで確かめるよう頼んだ。この時点では本物の録音を渡していなかった。

**何が起きたか、期待と何が違ったか**
Claude Code は合成音（高い雑音 → 低い音＋破裂音）を作って判定を書き、テストは真値どおりに通った。ところが実際のスチームで試すと、40〜60 秒のスチームが 14〜19 秒しか検出されなかった。渦に入ったあとの撹拌が背景の物音と同じくらい静かで、閾値を割って区間が途中で切れていた。テストが通っていたので、前提がずれていることに翌日まで気づかなかった。

**どう対処したか**
ボイスメモで本物の音を録り、自宅の Mac の中でスペクトログラムの絵にして、Claude Code と一緒に見た。私が「ここが泡入れ、27〜32 秒は追加の泡入れ」と耳で教え、判定を本物の音に合わせて作り直した（耳と ±0.4 秒で一致）。合成音のテストも実際の音の並びに作り直した。ここから「音を絵にして Claude に見せ、人が耳で教える」が、このプロダクトの育て方の柱になった。

## Claude を使った感想と改善してほしい点

**日本語や日本の業務で使う立場からの欠点と利点**
- 利点: 設計の判断（D1〜D23）や毎日の記録を、日本語のまま Claude Code と書き続けられた。コーチの返答も、日本語の擬音（キュルルル、ジュルジュル、チリチリ）を本人の言葉のまま使って返せた
- 欠点: Managed Agents の Dreaming（研究プレビュー）の申請フォームが gmail.com のアドレスを受け付けず、個人開発者は個人ドメインのアドレスを用意する必要があった
- 欠点: SSH 越しの Claude Code では、Mac のキーチェーンがロックされて iOS の署名が通らない。セッションを閉じると、そこから起動したサーバーも止まった（11-04、11-07 の2回、杯がタイムアウトした）
