## 11-03 企画の絞り込みから一周まで（[log](../log/2026-11-03.md)）

**起きたこと**
- 固定フレームで俯瞰撮影を試した。映像は取れたが、家庭の練習者には準備が重すぎた
- 完成写真を採点して直す点を1つ返すアプリが、すでに市場にあると分かった。スチームの音で診断するものはなかった
- Xcode を入れ、iOS アプリ・薄いサーバー・診断の待ち時間の計測スクリプトを書いた。無料の Apple ID で iPhone に入れて起動した
- iPhone → サーバー → 診断 → アプリに表示、の一周が、固定の診断で回った。USB 経由でも Wi-Fi だけでも通った
- 待ち時間を測った。Managed Agents＋Outcomes は約68秒、Messages API は約15秒だった
- 本物の診断（Managed Agents）でも一周が回った。ダミーの杯で101秒・190秒だった
- Dreaming（研究プレビュー）を申請した。フォームは Gmail を受け付けず、個人ドメインのアドレスで出した

**変えたこと・決めたこと**
- 撮影をやめ、置くだけの録音にする（D1）
- 製品の主語をラテアートからミルクスチームに移す。工程はエア入れ／撹拌の2つにし、注ぎは診断しない（D10）
- 診断を「原因1つ・直す点1つ・次の杯の予測1つ」にし、次の杯で当否を確かめる（D7、D8）
- 最初の一周は手動区切りで回し、自動区切りと包絡は後回しにする（D11）
- 無料の Apple ID で開発する。リモートのプッシュ通知は使わず、アプリが結果を取りに行く（D12）
- 1杯ごとの診断は Managed Agents＋Outcomes で回す（D13）

**つまずいたこと**
- App Store の CLI（mas）は、サインインしていないと進まなかった。Homebrew 版の xcodes は macOS 27 でビルドできなかった。Xcode は本人が App Store から入れた
- SSH 経由のシェルからは、キーチェーンがロックされていて署名できなかった（`errSecInternalComponent`）
- iOS の最初の送信が、ローカルネットワークの許可が出るまで失敗した

## 11-04 実際のスチームで初めての診断（[log](../log/2026-11-04.md)）

**起きたこと**
- 朝、サーバーが止まっていた。前のセッションを閉じたときに一緒に止まったため。最初の送信は時間切れになり、アプリでは「送信中」のまま固まった
- 実際のスチームで2杯を診断した（104秒・127秒）。2杯目は、1杯目の予測（ゴボゴボが減る）を「当たり」と判定した。そのうえで、他の条件も変わったので直し方だけの効果とは言い切れない、と断った。予測を次の杯で検証する流れが、実際の杯で初めて回った
- 一方で、40〜60秒のスチームが14〜19秒しか検出されなかった。撹拌の安定度は0に張り付いた。1杯目は、前の杯としてダミーと比べていた。写真はピッチャーがほぼ空で、泡が読めなかった
- 本人からスチームの手順と音の聞こえ方を聞いた。空だし → キュルルル → ジュルジュル → 渦 → キュルキュル → 空だし

**変えたこと・決めたこと**
- 検出の閾値をゆるめ、包絡（0.1秒ごとの3帯域）をサーバーへ送って保存する（D14）
- 起動時に「送信中」で止まった杯を立て直す。送信は30秒で切る
- ダミーの杯をサーバーの記録から外した
- 記録手順に「ピッチャーに少しミルクを残してから撮る」を足した

**つまずいたこと**
- キーチェーンを Mac の画面側で解錠しても、SSH 側には効かなかった。Claude Code の入力欄から `!` で解錠する必要がある

## 11-05 実際の音の形を見て、判定を作り直す（[log](../log/2026-11-05.md)）

**起きたこと**
- 本人が「音を送ってAIで解析できないか」と問うた。Claude は音を直接聞けないこと、「生の音声を端末外に出さない」約束を崩すことを説明し、開発用にボイスメモを本人の Mac の中で解析する形にした
- ボイスメモ1本（67秒）を解析した。渦の撹拌相は背景より +2〜5 dB しかなく、区間が途中で切れていた。いちばん高い音は泡入れではなく、蒸気を出した直後の「キュルルル」だった。泡入れの「ジュルジュル」の特徴は、音の高さではなく音量の細かい揺れだった
- 本人の評価は「泡が少し多かった」

**変えたこと・決めたこと**
- スチームの区間と相の判定を作り直した（D15）。この録音では、スチーム56秒、キュルルル4.6秒、泡入れ29%になった（前の判定では14〜19秒）
- 合成音のテストを、実際の並びに合わせて作り直した
- コーチのプロンプトに、本人の音の並びと新しい特徴量の意味を書いた。エージェントはプロンプトの変更に合わせて新しい版に更新されるようにした
- サーバーの診断方式の既定値を `managed` にした

**まだのこと**
- 2本目のボイスメモで新しい判定を確かめる
- 新しい判定を iPhone に入れる（キーチェーンの解錠が必要）
- GitHub へのプッシュ。SSH の鍵が読み込まれておらず、`57329a7` が手元に残っている

## 11-06 エージェントに音を解析させる（[log](../log/2026-11-06.md)）

**起きたこと**
- Managed Agents のエージェントに、ボイスメモから作った数値データを渡して境を答えさせた。はっきりした境は ±0.2 秒で当たったが、泡入れ→渦の境は 23 / 30 / 32 秒に割れた
- 本人に聞くと、泡入れは 16〜23 秒で、27〜32 秒に追加で泡入れしていた。エージェントが割れたのは、泡入れが2回あったからだった
- 撹拌中のチリチリは 4〜8 kHz の短い山だと、答え合わせ図で本人と確かめた

**変えたこと・決めたこと**
- 判定は端末の数値のまま、絵は Claude が音を読む場面に使う（D16）
- 泡入れを1回と決めつけず、追加の泡入れを別に数える（D17）。本人の耳と ±0.4 秒で一致

## 11-07 一緒に育つコーチへ（[log](../log/2026-11-07.md)）

**起きたこと**
- 画像だけで判定させる実験をした。はっきりした境は当たるが、キュルルル・追加の泡入れ・渦への境でアプリの判定に劣り、回ごとにぶれた
- 本人から、スチームのやり方は人によって違い、マシンによって長さも 15〜60 秒と違う、と聞いた。汎用の採点器は作れないので、その人の杯どうしを比べ、AI も人も初心者から一緒に育つコーチにする、と決めた
- 夜の振り返りを初めて回した。検出の誤りから「スチームを 19 秒にそろえる」というテーマを出したので、本人が「コーチに教える」で正した
- 本人の提案で、コーチに音の絵と包絡も渡し、判定の閾値をコーチが提案して本人が承認する仕組みを作った
- 本人の指示で、練習の音を全部、自宅の Mac のサーバーに送るようにした（約束を「家の外に出さない」に改めた）
- 昼の杯で、コーチが音の絵から「アプリの止めた線が早すぎる」と書いた。保存した音で確かめると正しく、渦が部屋の物音と同じ大きさで判定が途中で切れていた。続きを高域と低域の差で見るように直し、判定を v2 にした
- 夜の振り返りで、教わったこと（続けて淹れると勢いが弱まる）を使って予測の外れを説明し、明日のテーマを決めた

**変えたこと・決めたこと**
- D18 一緒に育つコーチ（記憶、夜の振り返り、コーチに教える）
- D19 コーチに音の絵と包絡も渡す
- D20 閾値はコーチが提案し、本人が承認する（判定の版）
- D21 練習の音を全部、自宅の Mac のサーバーへ。音声は家の外に出さない
- D22 スチームの続きを高域と低域の差で判定する（v2）

**つまずいたこと**
- 音を 16 kHz に間引くと判定がずれた。間引かずに送る
- サーバーがセッションの終わりとともに止まり、杯がタイムアウトした。古い版のアプリで送り直して、杯が二重になった
- コーチが診断の JSON をファイルに書いて終え、取りこぼした。出力ファイルからも読むようにした
