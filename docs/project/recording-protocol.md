# 記録プロトコル

検証用データを集めるときの手順。製品としての操作（[overview.md](overview.md#ユーザー操作練習1回あたり)）と同じ手軽さを保つ。

## 毎回の手順

1. 練習の開始時に「開始」を押し、スマホを手元の邪魔にならない場所に置く。位置合わせ、ピント、窓の開閉、照明の準備はしない
2. 注ぎ終わったら、ピッチャーの残りのミルクが見えるように手持ちで1枚撮る（通知から）。**ピッチャーには少しミルクを残してから撮る**（空に近いと泡の大きさ・固さ・艶が読めない。[log/2026-11-04.md](../log/2026-11-04.md)）。カップを隣に置いて一緒に写してもよいが、採点には使わない（[decisions.md D10](decisions.md#d10-対象をミルクスチームに特化し工程をエア入れ撹拌の2つにする)）。スチーム直後には撮らない（[decisions.md D5](decisions.md#d5-完成写真にピッチャーの残りを入れる)）
3. 各杯に自己評価を残す。検証用の正解ラベルになるため、**検証期間中は必須**（製品としては任意）
4. 2杯目以降は、前の杯の「直す点」を1つだけ試す。複数を同時に変えると予測の当否が判定できない

## 条件の固定

- 練習用ミルクは同一銘柄を通しで使う（音と泡の条件を固定するため）。記録期間分をまとめて確保する
- 豆は手元の在庫を使う
- マシン、ノズルの穴数、ピッチャー容量、ミルク量は `/profile.md` に書き、期間中は変えない

## 練習仲間の杯

期間中に練習仲間1〜2人の杯を同じ手順で通す。本人以外の機材とミルクでも診断が成り立つかの確認と、デモで添える一言の反応のため。相手は承認済み参加者でなくてよい。コードを書かず、使って意見を言うだけなら問題ない（[kickoff.md](../hackathon/kickoff.md#ルールの補足)）。

## アプリ完成前の代替手順

アプリができるまでは、ボイスメモで練習を通し録音し、ピッチャーの残りの写真はカメラで撮っておく。あとでメモリストアに流し込み、夜の振り返りを見せられる日数を稼ぐ。

## 目標量

2026-11-03〜11-07 に1日3杯以上、計15〜20杯。記録は 11-07 夕方までに終える。日々の観測は [docs/log/](../log/) に残す。
