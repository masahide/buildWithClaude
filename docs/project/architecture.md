# 全体構成

```
iPhoneアプリ ──特徴量+写真──> 薄いサーバー ──セッション開始──> Managed Agents
     ^                            |    ^                         (コーチ)
     └──────プッシュ通知────────────┘    └──────Webhook──────────────┘
                                                    ^
                              夜のスケジュール実行 ─┘（メモリストアを更新）
```

| コンポーネント | 役割 |
| --- | --- |
| iPhone アプリ | 音と写真を集め、音響特徴量を端末内で計算する |
| 薄いサーバー | API キーを持つ中継役。セッション開始、Webhook 受信、プッシュ通知 |
| Managed Agents | コーチ本体。1杯ごとの診断と夜の振り返り |

## iPhone アプリ（音と写真を集める）

- バックグラウンドで録音する。練習開始時の数秒で背景音量を測り、基準にする
- スチーム区間の検出: 基準に対する帯域エネルギーの比で鳴り始めと鳴り終わりを判定する。短い途切れ（空ぶかしなど）は1区間に統合する
- 音響特徴量を端末内で計算する。端末差・置き場所の差・窓を開けた環境の差に耐えるため、**すべて相対値**にする

  | 特徴量 | 意味 |
  | --- | --- |
  | エア入れ相の時間比率 | 「紙を裂く音」が続く時間の割合 |
  | 移行タイミング | エア入れ相から撹拌相（渦に入って静かになる）へ移るタイミング |
  | 撹拌相の安定度 | 撹拌相の音の揺らぎの小ささ |
  | 大きな泡の破裂音の回数 | 「ゴボゴボ」の回数 |

- 区間が終わると通知 → 完成写真1枚 → 任意で自己評価
- 特徴量・写真・自己評価をサーバーへ送信し、診断結果はプッシュ通知で受け取る
- 生の音声は送信しない

## 薄いサーバー（API キーを持つ中継役）

- `POST /cups`: 写真をアップロードし、Managed Agents のセッションを開始して特徴量と写真を渡す。Outcomes のルーブリックを定義する
- Webhook 受信: セッション終了（`session.status_idled` など）で結果を取り出し、APNs でプッシュ通知する
- 朝の通知: 夜の振り返りが書いた「今日のテーマ」を決まった時刻に通知する
- API キーは環境変数で管理し、公開リポジトリに入れない
- インフラは本人の得意なものでよい。処理は上記だけに留める

## Managed Agents（コーチ本体）

### エージェント「コーチ」

1体だけ置く。役割は「原因の工程を特定し、次の1杯で直す点を1つだけ返す」。

原因は、スチーム（音）→ ミルク → 注ぎ（完成形からの推定）の順に割り当てる。注ぎの動作は動画を使わず完成形から推定する（例: 縦に伸びた → 最後の抜きが長い）。

### メモリストア（ユーザーごとに1つ）

各セッションは白紙で始まるため、杯をまたいだ記憶はメモリストアに持たせる。期間中に作った内容を事前に投入する。

| パス | 中身 | 書く人 |
| --- | --- | --- |
| `/profile.md` | 固定条件（ミルク銘柄、マシン、豆、カップ、目標技法スローハート） | 本人（事前投入） |
| `/rubric.md` | 症状→原因→練習法の表。競技会の審査基準と本人の失敗ログから期間中に新規作成し、育てる | 本人＋コーチ |
| `/cups/YYYY-MM-DD-N.md` | 1杯ごとの特徴量、写真の所見、診断、自己評価 | コーチ |
| `/tendencies.md` | 杯をまたいだ癖のまとめ | 夜の振り返り |
| `/today.md` | 今日のテーマ1つ | 夜の振り返り |

### 1杯ごとの診断セッション＋Outcomes

採点役が、次のルーブリックを満たさない回答を差し戻す。

- 原因の工程はちょうど1つ（スチーム／ミルク／注ぎ）
- 直す点はちょうど1つ。複数の指摘を含まない
- 根拠が、今回の音響特徴量か写真の所見のどちらかにある
- `/tendencies.md` と過去の杯の記録に矛盾しない。矛盾する場合はその理由を述べる
- 次の1杯で実行できる具体的な行動になっている（「意識する」だけで終わらない）

診断の待ち時間によっては、1杯ごとの診断を Messages API に切り替える可能性がある（[plan.md](plan.md#今日11-03確かめること) の確認項目2）。

### 夜の振り返り（スケジュール実行）

毎晩、メモリストアを付けたセッションを cron で起動する。

1. その日の `/cups/` を読む
2. 杯をまたいだ癖を見つけて `/tendencies.md` を更新する（例: エア入れ相が長い杯ほど輪郭が滲む）
3. 明日のテーマ1つを `/today.md` に書く

Dreaming（研究プレビュー、申請制）の承認が下りたら、この自前の振り返りを Dreaming に置き換える。承認が来なくても体験は成立する。

## 運用上の注意

Managed Agents のセッション履歴は削除するまで残る。メモリストアとアップロードしたファイルはセッションを消しても残るため、提出後に不要なら個別に削除する。
