# プロダクト概要: ラテアートAIコーチ

家庭でラテアートを練習する人のための、**ミルクスチームに特化した**練習に溶け込むコーチ。スマホを置いて練習するだけで、スチームの音から1杯ごとに「原因の工程」「次の1杯で直す点ひとつ」「次の杯で起きるはずの変化」が届く。次の杯でその予測が当たったかを確かめ、翌朝には前日の杯をまたいだ癖と今日のテーマが届く。

ハッカソンではテーマ1「あなたにしかない深さを。」で応募する。完成写真を採点するアプリは既にあり（[log/2026-11-03.md](../log/2026-11-03.md#既存アプリの調査)）、主催ガイドも「画像解析ツール」を避けるべき例に挙げている。そこで製品の主語はラテアートではなくスチームに置き、**音で工程を聴き分け、次の1杯で仮説を検証するコーチ**として設計する（[decisions.md D10](decisions.md#d10-対象をミルクスチームに特化し工程をエア入れ撹拌の2つにする)）。ラテアートは、見えないスチームの失敗が目に見える形で現れる場として、困りごとの導入に使う。

## 誰が、何に困っているか

ラテアートの出来はミルクのスチームで大半が決まるが、スチームの正解は熟練者の耳と手の中にある。「紙を裂く音」「渦に入って静かになる」という言葉と動画はあっても、自分の音がそれに合っているかは一人では確かめられない。

家で一人で練習すると、次の3つが重なる。

- **自分の杯へのフィードバックがゼロ。** 隣に先生がいない
- **原因の工程を切り分けられない。** スチームは手元の中で30秒で終わり、見えず、結果は注ぎと混ざって初めて現れる。失敗してもエア入れか撹拌か分からず、同じ失敗を繰り返す
- **1杯のコストが高い。** 牛乳と豆と数分がかかり、やみくもに回数を増やせない。だから1杯ごとのフィードバックの価値が高い

このコーチは、熟練者が耳でやっている判断を、家で一人で練習する人の横に置く。

## 設計原則

撮影方式を試行錯誤した結果（[decisions.md D1](decisions.md#d1-固定フレーム撮影をやめ置くだけの録音にする)）と、音で分かること・分からないことの整理（[decisions.md D7](decisions.md#d7-診断を仮説と予測の形にし次の杯で検証する)）から、次の3つを原則とした。

1. **ユーザーは撮影のことを考えない。** ラテを作ること以外の操作は、練習の最初に1回と、1杯ごとに写真1枚だけ
2. **コーチの方から来る。** 杯の区切りはアプリが音で拾い、診断も翌朝の一言もコーチの側から届く
3. **コーチは正解を押し付けず、次の杯で検証する。** 直す点には「次の杯でこう変わるはず」という予測を添え、当たった直し方だけを本人の正解として残す

## 工程の区分

原因は次の2工程のちょうど1つに割り当てる（[decisions.md D10](decisions.md#d10-対象をミルクスチームに特化し工程をエア入れ撹拌の2つにする)）。音の2相と工程が1対1に対応する。

| 工程 | 何をしているか | 主な観測 |
| --- | --- | --- |
| エア入れ | ノズルを液面近くに置き、空気を入れる | 音（エア入れ相） |
| 撹拌 | ノズルを沈め、渦で泡を折り込む | 音（撹拌相）、ピッチャーの残り |

注ぎは診断しない。カップの模様はスチームの結果が見える場として扱い、採点の対象にしない。ミルクの銘柄・量・温度やマシンは工程ではなく条件として扱い、プロフィールに持たせる。

## 対象ユーザーと前提

- 家庭でラテアートを練習する個人。まず本人、期間中に練習仲間1〜2人
- 前提機材は iPhone のみ。外付けマイク・ライト・スタンドは使わない
- 構成は iOS ネイティブアプリ＋薄いサーバー＋Claude Managed Agents（[architecture.md](architecture.md)）

## ユーザー操作（練習1回あたり）

1. 練習を始めるときに「開始」を1回押す。スマホは手元の邪魔にならない場所に置く（ロックしてよい、位置は問わない）
2. スチームが終わるとアプリが通知を出す。注ぎ終わったら、**ピッチャーの残り**を手持ちで1枚撮る。カップを並べて写してもよいが任意（[decisions.md D5](decisions.md#d5-完成写真にピッチャーの残りを入れる)、[D10](decisions.md#d10-対象をミルクスチームに特化し工程をエア入れ撹拌の2つにする)）
3. （任意）1タップで自己評価する
4. 練習が終わったら「終了」を押す。押し忘れても、一定時間スチーム音がなければ自動で終了する

## 返ってくるもの

| タイミング | 内容 | 届け方 |
| --- | --- | --- |
| 1杯ごと | 原因の工程1つ、次の1杯で直す点1つ、次の杯で起きるはずの変化1つ | プッシュ通知 |
| 次の杯 | 前の予測が当たったか（効いた／効かなかった） | 診断に添える |
| 翌朝 | 前日の杯をまたいだ癖と、今日のテーマ1つ | プッシュ通知 |
| いつでも | 「あなたの正解」: 効いた直し方の一覧 | アプリ内 |

直す点は、耳・手・時間で実行できる言葉に限る。「液面下1cm」のように作業中に測れない指示は出さない（[decisions.md D8](decisions.md#d8-指示は耳手時間で実行できる言葉に限る)）。

## プライバシー

生の音声は端末から出さない。端末で計算した音響特徴量（スカラー値と、0.1秒ごとの帯域エネルギーの相対値の数列）と、ピッチャーの残りの写真だけを送る。数列からは会話を復元できない（[decisions.md D6](decisions.md#d6-音響特徴量に包絡を加える)）。

## 分かること、分からないこと

音と写真で判定できるのは工程の結果であり、動作そのものではない。渦の回転方向や縦横の撹拌のバランスは聞こえない。だからコーチは動作を見るのではなく、症状から原因の工程を推定し、直し方を指示し、次の杯の結果で検証する。この限界は [decisions.md D9](decisions.md#d9-音で分からないものを明文化する) に記し、README とデモでも明言する。

## 拡張性

家庭のラテアート練習を第一の場面とする。スチームはミルクを使う飲み物すべてに共通し、カフェの新人教育でも「耳で覚えろ」としか教えられない工程なので、対象はそこへ広がりうる。さらに「音と結果写真で工程を診断し、次の1回で検証するコーチ」という仕組みは、他の伝承的な手技にも展開できるように設計する。いずれも README の「次にやること」に書き、製品の語りは家で一人の練習者に留める。
